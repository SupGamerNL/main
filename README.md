## What this is

A small static website (plain HTML, CSS and JavaScript: no framework, no build step, no third-party scripts, no analytics) published with GitHub Pages at <https://supgamernl.github.io/main/>. It shows my creations, hosts downloads for the communities I make things for, and is driven by one data file: `data/projects.js`. Python is only used by optional helper scripts in `tools/`.

## How the pages fit together

- **Home (`index.html`)** is the landing page and the project list in one: introduction, search, filters, sorting and a card per project.
- **Project pages (`projects/<id>/`)** are made from `project.html` and one entry in `data/projects.js`. Each has its own title, description, preview image and structured data in the HTML itself (so link previews and search engines work without JavaScript), a short summary for visitors without JavaScript, and the same JavaScript that fills in the full page (compatibility, downloads, screenshots, changelog, timeline, related projects).
- **`project.html?id=<id>`** keeps working as a fallback. If a project page has not been generated yet, `404.html` sends `projects/<id>/` there, so a link never dies. Run the update script to get the real page.
- **Gallery** collects the screenshots of every project (plus `data/gallery.js`) with a filter per project.
- **About** is mostly static text plus the project overview and my profile links.
- Every project page carries a breadcrumb trail (Home, Creations, category, project) and a "You might also be interested in" section. Both are built from the data: related projects are scored on category, shared loader, shared game versions, game or engine, and tags.

## Adding a project

1. Open `data/projects.js`, copy an existing project block and give it a new unique `id`. Use lowercase letters, numbers and dashes only (`my-new-mod`): the id becomes a folder name, and GitHub Pages is case-sensitive even though Windows is not.
2. Fill in the name, category, description, tags, links and the `page` section.
3. Optional: put screenshots in `assets/img/` and downloads in `downloads/<community>/`, then list them (see Downloads and Adding screenshots below).
4. Run `python tools/update-site.py`. It checks the entry, refreshes file sizes, the sitemap and the SEO lists, and writes `projects/<id>/` and `share/<id>/`.
5. Upload everything that changed (see "Updating the site" below).

The card on the home page and the project page come from that one entry.

### Optional extras per project

All of these can be left out. The full explanation is in the comment at the top of `data/projects.js`.

- `status`: `"released"`, `"in-development"`, `"planned"`, `"on-hold"` or `"archived"`. Shows a status badge on the card and the page.
- `cover`: a file name from the project's screenshots folder. Without it the first screenshot is used. No screenshots, no cover.
- `support`: what the project runs on, one row per version line: `{ label?, game?, engine?, versions?, loader?, requires?, note? }`. Shown as a short line on the card, as the "Compatibility" section on the page, and it feeds search, the version and loader filters, and the related projects.
- `released` / `updated`: `"2026"`, `"2026-11"` or `"2026-11-04"`. Used by the date sort orders. If left out, the oldest and newest date found in the changelog and timeline are used. Projects with no date at all are listed last.
- `changelog`: `[{ version, date?, changes: [...] }]`, newest first. Shows a "Changelog" section.
- `timeline`: `[{ date, title, text? }]`, oldest first. Shows a "Timeline" section.
- `credits`: a short text for a "Credits & license" section (asset licenses, fan-project disclaimers, thanks).
- `issues`: where "Report a bug" leads for this project (default: the Issues page from `data/config.js`).
- In `page.sections`, next to `text` and `chips` you can add `list: ["...", "..."]` for bullet points.

## Search, filters and sorting

The search box looks through names, descriptions, categories, tags, versions, loaders, required mods, status, download labels and the material chips. A search word has to match the start of a word, so `forge` finds Forge, `neoforge` finds NeoForge and `1.12` finds 1.12.2. Several words must all match. Press `/` to jump to the search box.

Next to the category buttons, **Filters** opens status chips, a game-version dropdown and a loader dropdown (their options are read from the `support` rows, with counts), and **Sort by** offers: default order, name A to Z, name Z to A, recently updated, recently released, oldest first, and development status (in development, planned, released, on hold, archived; the order is the `STATUS_ORDER` list in `assets/js/script.js`). Everything works together and is stored in the address (`index.html?q=forge&cat=Minecraft%20Mods&status=released&ver=1.12.2&loader=Forge&sort=az`), so a view can be shared or bookmarked.

## Appearance settings and accessibility

The settings button in the navigation bar opens an Appearance panel (saved on the visitor's own device only):

- **Theme:** dark (default) or light.
- **Contrast:** low, default or high. High also underlines links and thickens the keyboard focus ring. The system's "more/less contrast" setting is followed until a choice is made.
- **Text size:** small, normal, large or XL (everything is sized in `rem`, so the whole site scales).
- **Motion:** full, reduced (no looping or background animation, no intro, no cursor glow) or off (nothing moves, no smooth scrolling). The system's "reduce motion" setting is followed until a choice is made.

The themes are variable blocks at the top of `assets/css/style.css`: add a block there to add a theme. A tiny inline script in the `<head>` of every page applies the saved choices before the page is drawn, so nothing flashes.

Keyboard and screen reader support: a "Skip to content" link on every page, a clearly visible focus ring everywhere (the card, row or group around the focused element lights up too), labelled landmarks, breadcrumbs, a focus-safe filter bar, Escape closes panels and the lightbox, arrow keys move through the lightbox, and a back-to-top button appears on long pages. The pages were checked with the axe accessibility checker in every theme (no violations), which is a good baseline but not a guarantee.

## Boot intro

The home page plays a short system boot intro once per browser session. It is skipped for reduced motion (system or site setting), when the page was opened with a filter or `#section` link, and can be skipped with the button or Escape. `intro.css` and `intro.js` are only downloaded when it plays. Timings are in the `CFG` block at the top of `assets/js/intro.js`.

## Copy-link buttons

Every project card has a small copy icon in its top-right corner (it copies the project's share link), every row in a project's "Downloads" has a copy icon (it copies the direct download link: the file on this site, or the GitHub Release file), and the "Copy share link" button on a project page does the same as the card icon. After copying, a small "Link copied!" notification pops up at the bottom of the screen for about two seconds. The code is `assets/js/copy.js` (script) and the "Copy-to-clipboard buttons" block at the end of `assets/css/style.css` (looks). To add a copy button anywhere else in a script: `Copy.button({ text: "https://...", label: "Copy link" })` gives you the button, and `Copy.text("https://...")` copies straight away. If the browser blocks copying, a box with the link appears so it can be copied by hand.

## Share links

Post the project page address itself, for example `https://supgamernl.github.io/main/projects/mo-ores-n-tools/`. Each generated page carries the project's own title, description and cover image, so Discord, Reddit, CurseForge descriptions and similar apps show a proper preview even though they don't run JavaScript. The copy-link buttons on the cards and project pages copy exactly this address.

Older links of the form `share/<id>/` and `project.html?id=<id>` still work. Chat apps cache previews, so a changed cover may show up late in an already-shared link. Some apps may not show WebP images in previews; if one doesn't, a JPG version can be generated.

## Changelogs

A project page shows a "Changelog" section when it has entries. Two ways:

- **By hand:** a `changelog` list in the project in `data/projects.js` (see the comment at the top of that file). This always wins.
- **Fetched:** `python tools/fetch-changelogs.py` reads the CurseForge and Modrinth links of each project, takes the "What's new" text of the newest files and writes `data/changelogs.js`. Modrinth needs nothing. CurseForge needs a free API key (see the top of the script; keep the key out of the repo). `--only <id>`, `--limit N` and `--dry-run` are available. Then run `python tools/update-site.py` and upload `data/changelogs.js`.

## Bug reports, questions and feedback

Every project page has a "Report a bug" and a "Questions & feedback" button, and the footer links to both. Bugs lead to the Issues page of `SupGamerNL/main`, questions and ideas to its Discussions (both set in `data/config.js`; Issues and Discussions must be switched on for that repo). A project can use its own repo for bugs by adding `issues: "https://github.com/SupGamerNL/<repo>/issues"` to it in `data/projects.js`.

## Adding screenshots

The quick way (needs Python and Pillow once: `pip install pillow`):

```bash
python tools/add-screenshots.py <project-id> <screenshot files or a folder>
python tools/add-screenshots.py general <screenshot files or a folder>
```

It writes the full-size WebP (max 1920px wide, quality 85) to `assets/img/<project-id>/` and the thumbnail (640px wide, quality 80) to `assets/img/<project-id>/thumbs/`, with the same file name in both, and prints the `gallery` lines to paste into `data/projects.js` (or `data/gallery.js` for `general`). Captions are left as `TODO`, since only you know what a screenshot shows. Existing files are never replaced unless you add `--overwrite`.

By hand: save the images as described above and add `{ file: "name.webp", caption: "What it shows" }` to the project's `gallery` list. Screenshots show up on the project page and in the main gallery automatically. General screenshots live in `assets/img/general/` (and `thumbs/`) and are listed in `data/gallery.js`.

## Navigation

The navigation bar is part of the HTML of every page (`index.html`, `project.html`, `gallery.html`, `about.html`, `404.html`), and `update-site.py` copies it into the generated project pages from `project.html`. To add a page, add a link to the `<ul class="nav-links">` list in each of those files, then run the update script. On phones and tablets the bar turns into a burger menu, handled by `assets/js/ui.js`.

## SEO

- Every page has its own title, description, canonical link, Open Graph and Twitter tags. `index.html` and `gallery.html` hold them in the HTML. Each generated project page holds its own (title, description, canonical `projects/<id>/`, share image = the cover or first screenshot else `icon-image.png`, and `CreativeWork` + breadcrumb structured data), and `assets/js/project.js` sets the same values again at runtime, so `project.html?id=<id>` is consistent too.
- `index.html` carries `WebSite` (with a search action that points at `?q=`), `Person` and `ItemList` structured data, plus a plain list of all projects for visitors without JavaScript. `about.html` carries `ProfilePage` data. All of it is generated by `python tools/update-site.py`.
- `sitemap.xml` lists the home page, the About page, the gallery and every project page.
- To change the site address, edit `data/config.js` and the few hard-coded `supgamernl.github.io/main` URLs in the HTML heads and `404.html` (search for them), then run the update script.

## Downloads

Every project can offer its files in two ways, and the project page shows a "Downloads" section with a button for each:

- **Download**: the file straight from this site, from the `downloads/` folder (a folder per community, then per project, for example `downloads/minecraft/mods/bnm/`).
- **GitHub Release**: a direct download of the same file from a GitHub Release, plus a small "Release page" link.

Both are set in the `downloads` list of a project in `data/projects.js`:

```js
downloads: [
  { label: "Hotel of Secrets", note: "Minecraft 1.8.9",
    release: { tag: "minecraft-map", asset: "Hotel.of.Secrets.zip" } }
]
```

- `file` is the path inside this repo. `release` is the Release tag and the exact asset name. Either one can be left out. `group` and `note` are optional.
- Browsers can't list folders, so every file needs one entry. Spaces, apostrophes and brackets in file names are handled by the site.
- GitHub rewrites spaces and special characters in release asset names, so give assets a clean name (letters, numbers, dashes, dots) and use that exact name in `asset`.
- Release buttons show while `RELEASES_LIVE` at the top of `data/projects.js` is `true`. Only add a `release` once that Release really exists, otherwise the button leads to a 404 page.
- Files over 100 MB can't live in the repo, so those go in a Release only (Hotel of Secrets and Veldoria do this).
- Direct link format: `https://github.com/<owner>/<repo>/releases/download/<tag>/<asset>`.
- Each file in a GitHub Release can be up to 2 GB.

### File sizes

Sizes are filled in automatically, so there is no `size` to type. `python tools/update-site.py` measures every file in `downloads/` and asks GitHub for the size of every Release asset, and stores them in `data/sizes.js`. The browser also re-checks files on this site live, so a replaced file shows its new size even before the script is run again. (A `size: "..."` on a download still works as a last-resort fallback.)

## Updating the site

1. After changing `data/projects.js`, screenshots or downloads, run `python tools/update-site.py` from the repo root.
2. Copy the changed files into the repo (GitHub Desktop shows them): besides your own edits that is usually `data/sizes.js`, `sitemap.xml`, `index.html`, `about.html`, `project.html`, `projects/` and `share/`. Delete old or renamed files.
3. Commit and push in one go (GitHub Pages has a soft limit of about 10 builds per hour), then hard refresh (Ctrl+F5) because browsers cache old files.

If you forget step 1 for a new project, its card still shows up and its page still works through the fallback, only the link preview and search-engine tags are missing until the script has been run.

### GitHub Pages notes

- The site is static: there are no server-side redirects or rewrites, so old addresses are kept as small pages or handled by `404.html`.
- Addresses are case-sensitive on GitHub Pages: keep file, folder and project names lowercase with dashes.
- Files over 100 MB can't be in the repo (use a Release). The published site should stay under 1 GB.
- Pages are served without Jekyll (`.nojekyll`), so shared parts such as the navigation are copied into each HTML file rather than included.
